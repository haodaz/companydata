# 把 Forage 岗位模拟转译成「真活」出题样本骨架

背景：「真活」平台给企业出真实业务题。出题时会从样本库里挑 0–2 份「好题骨架」当**结构参照**（学它怎么推进、每步给什么、评什么），内容换成别的企业此刻的真实问题。
这里的输入是 Forage 上公开的岗位模拟的**外层信息**（扮演谁、目标、每个任务要做什么 / 会学到什么、每个任务里的步骤类型）。你要把每个模拟**理解后用中文重新写成骨架**——是转译，不是逐字翻译：用自己的话、中文职场说法，保留结构和考点。不要编造原文没有的数字、客户名、条款号。

## 输入
一个 JSON 数组，每条：sim_id, company, title, tagline, career_areas, role（你扮演谁）, goal（目标）, skills, difficulty（introductory / intermediate / advanced）, time, tasks。
tasks 里每个任务：title, tagline, do（要做的事）, learn（会学到）, time, difficulty, steps（步骤列表，`c:` 开头是讲解内容，`s:` 开头是要交的东西：s:file-upload 上传文件、s:multiple-choice 选择题、s:text / s:free-text 文字作答、s:video 录视频 …；`c:example-answer` 表示做完有示例答案）。
有的模拟 role / goal 为空，就从 title、tagline、tasks 里理解。

## 输出（每条输入对应一条，顺序一致）
写成一个 JSON 数组到指定的输出文件，每条：
```json
{
  "sim_id": "原样抄",
  "skeleton": {
    "title": "中文标题，8–20 字，说清这个岗位在干什么活",
    "summary": "两三句中文：扮演谁、在什么场景、分几步推进、考什么",
    "problem_type": "题型，如 交易文件审阅与起草 / 尽职调查 / 财务建模 / 市场进入 / 数据分析 / 软件功能开发 / 客户沟通",
    "industry": "中文行业或职业方向：法律 / 咨询 / 银行金融 / 会计 / 软件工程 / 数据 / 市场营销 / 人力资源 …",
    "difficulty": "低 | 中 | 高（introductory→低，intermediate→中，advanced→高）",
    "format": "岗位模拟",
    "stages": [
      { "id": "t1", "type": "judgement", "question": "这一步要候选人做什么（来自 do，中文，具体到交付物）",
        "reveal": "这一步给候选人什么（材料、文件、数据、背景讲解；从 tagline 和 steps 的讲解标题推断，如「GMRA 条款摘录、内部检查清单、违约事件条款讲解」）",
        "expected": "评审看什么（来自 learn，改写成「评审看：……」，3 条左右，用分号隔开）", "calc": [] }
    ],
    "exhibits": [ { "title": "材料名", "desc": "它是什么、这一步怎么用" } ],
    "style_notes": ["3–5 条：这个模拟作为题目「好」在哪、出题时可借鉴的手法"]
  },
  "tags": ["4–8 个中文标签：职业方向、业务领域、核心技能"],
  "occupation_name": "中文职业名，如 律师（衍生品与结构化融资）/ 管理咨询顾问 / 投资银行分析师 / 软件工程师",
  "time": "中文时长，如 3–4 小时"
}
```

## 规则
- 每个 task 一个 stage，按原顺序，id 用 t1、t2、t3…。
- stage.type 只能是：structuring（搭框架 / 做计划 / 拆问题）、judgement（审阅 / 分析 / 判断 / 找问题）、numeracy（测算 / 建模 / 估值 / 算数）、creativity（出方案 / 想点子 / 设计）、synthesis（写成交付物：邮件、备忘录、汇报、条款、意见书、演示）、other（写代码、实现功能等）。按这一步的核心动作选。
- calc 一律空数组（外层信息里没有可复核的数字）。
- exhibits：从各任务的讲解步骤和 tagline 里推断候选人会拿到的材料，2–6 条；推断不出就少写，别编。
- style_notes 要具体，从结构里看出来，比如：「先交代角色和项目团队，再分 N 个任务推进，难度逐步加」「每个任务先讲必要知识，再交作业，最后给示例答案对照」「交付物是真实工作产物（给客户的邮件、内部备忘录、条款草稿）」「中间穿插选择题确认理解」「一步只给当步需要的材料」。不要写空话。
- 企业名不要写进 title 和 summary（骨架要能换到别的企业），用「律所」「咨询公司」「投行」这类泛称；专业名词首次出现可中文后括号英文，如「全球回购主协议（GMRA）」。
- 中文要自然，像国内职场的说法；不要逐句直译。

## 交付
- 只写输出文件，不改别的文件，不联网，不调任何外部 API。
- 写完后用 `node -e "const d=require('<输出文件>'); console.log(d.length)"` 确认是合法 JSON、条数和输入一致。
- 最后回报：处理了几条、有没有 role/goal 为空或看不懂而写得比较薄的（列 sim_id）。
