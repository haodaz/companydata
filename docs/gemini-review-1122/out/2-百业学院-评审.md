## 一句话结论
百业学院用「五层显式材料 + 固定老师傅锚点 + 独立诚信检测」构建了一套极具可解释性的 AI 培养闭环，但在**培养价值的测量效度（前后测题目不对齐）、交付给买单客户的资产完整性（学完的知识无法打包带走）、以及多处核心流程断点（客户模型无法真连、方法课与私域包脱节）**上存在硬伤，修补后才能从「内部教务演示」变成可商业化交付的产品。

## 最该改的问题（按价值排序，5–8 条）

1. **前后测（入学考 vs 毕业考）测量对象错位，核心商业指标「培养增益（gain）」失真**
   - **证据**：`src/lib/college-train.ts` 的 `nextStep` 只挑一章跑入学考（`const entranceCh = d.chapters.find(c => c.kind === 'assessment') || d.chapters[0]; if (!d.chapters.some(c => c.before != null))`），而毕业考要考全部章节；`src/lib/college-admin.ts` 的 `recomputeEnrollment` 注释写着「入学考和毕业考同一口径：各章最好成绩的平均」，实际算成了「单章裸考分」对比「全章装配平均分」；`src/lib/college-leaderboard.ts` 直接用 `x.final_score - x.entrance_score` 算 `gain`。
   - **影响**：对买单客户和榜单读者极其严重。若 `assessment` 章本身偏难，会人为夸大培养增益；若偏易，甚至会出现「学完反而掉分」的荒谬结论，直接摧毁「培养价值量化」的信任基础。
   - **怎么改**：二选一落地，推荐方案 A（省成本且同尺）：① 在 `recomputeEnrollment` 中增加字段或逻辑，`gain` 只在**同时有 `before` 和 `after` 的相同章节集合**上计算差值；或者在 `entrance_exam` 时默认对全部 `kind === 'assessment'` 章节裸考，毕业成绩单分别展示「同题前后对比分」与「全课程结业分」。
   - **工作量**：小

2. **客户模型只有登记字段、没有调用链路，且不出成绩单，B 端付费闭环断裂**
   - **证据**：`src/lib/college-admin.ts` 的 `createStudent` 存了 `customer` 模型的 `api_style` 和 `endpoint`，但 `admitApplication` 只能靠正则硬猜平台已有模型（`MODEL_OPTIONS.find(...)`）；`src/lib/college-train.ts` 的 `needModel` 只认 `st?.model_id`，否则直接报错「这位学员还没接上模型接口」；`src/lib/college-transcript.ts` 的 `buildTranscript` 第 28 行硬编码 `if (!s || s.kind !== 'platform') return null;`；且全套代码没有任何导出「毕业模型已装配的五层 Prompt / 技能包」的接口。
   - **影响**：对付费客户致命。客户花钱送自研/微调模型入学，既没法用自己的 `endpoint` 考试，毕业了拿不到成绩单（只能管理员进后台看），买单后也拿不走训练沉淀下来的 `augmentSkill`（技能卡+笔记+错题规则），「派去向（`college_placements`）」只是一条数据库文本记录，没有实际交付物。
   - **怎么改**：① `loadEnrollment` 返回完整 `student` 连接信息（`model_id || custom_endpoint`），底层 `llm-client` 支持按 `student.endpoint + api_style` 路由请求；② `buildTranscript` 去掉 `s.kind !== 'platform'` 死拦截，改为支持带鉴权或分享 token 查看客户专属成绩单；③ 新增 `exportGraduatePack(enrollmentId)`，将 `augmentSkill` 拼装好的完整规则、方法卡、错题本导出为标准 System Prompt / JSON Skill 包，挂载到 `college_placements` 作为真实交付物。
   - **工作量**：中

3. **诚信（Honesty）检查在重评、成绩单、学籍最高分三个环节口径分裂，不及格也能拿 A 上榜**
   - **证据**：① `src/lib/college-admin.ts` 的 `enrollmentDetail` 中，`c.after` 取 `best(after)`（纯看 `score` 最大值，不管 `honesty.integrity`），导致某次作答编造数据但手艺得 85 分（`college-train.ts` 第 255 行注释明确「老实单独记、不压手艺分」），章节 `passed` 为 `false`，但 `final_score` 算出来是 85；② `src/lib/college-transcript.ts` 第 39 行 `const passed = courses.filter(c => (c.after ?? 0) >= 60)` 和 `letter(e.final_score)` 完全不看 `status === 'graduated'` 和 `integrity`，诚信挂科的课在成绩单上照拿 B 甚至 A、照算学分；③ `src/lib/college-train.ts` 的 `regradeEnrollment` 不传 `statement` 也不传 `given`（装配的技能卡和笔记），导致重评时学员引用技能卡里的数字会被 `numbersNotInSource` 误判成无来源编造。
   - **影响**：对评测公信力和教务运营严重冲击。刷分模型只要靠编造细节冲高手艺分，即便章节未通过，依然能在排行榜（`college-leaderboard.ts` 同样只读 `final_score`）和成绩单上拿高分；而教务点「重评（`regrade`）」反而会把好学生冤枉成不老实。
   - **怎么改**：① `enrollmentDetail` 计算 `after` 时，优先在 `!x.grading?.honesty?.integrity` 的合规作答里取最高分（若全有诚信问题，标记特殊状态或封顶 59）；② `buildTranscript` 判定课程通过改为 `c.status === 'graduated'`；③ `regradeEnrollment` 查询 `skill_submissions` 时补查 `with_skill_id` 及当时或当前的 `equipped` 文本传入 `gradeCollege` 的 `given`，并保留原 `grading.honesty.statement` 传入重评。
   - **工作量**：小

4. **「同题反复考 + 评卷漏题直塞错题本」导致毕业考退化为背答案刷分，缺乏泛化检验**
   - **证据**：`src/lib/college-train.ts` 的 `reflect` 把评卷意见里 `老师傅做了、我没做的关键动作（g.key_moves）` 和 `示范轨迹` 直接喂给模型提炼成 `nb.rules`；紧接着 `augmentSkill` 把 `nb.rules` 标上「必须遵守」塞进技能卡最前面，在**完全相同的 `chapter` 同一道题**上跑补考（`nextStep` → `补考 · ${c.title}`）；而唯一能检验泛化的 `runWorkExam`（真活考），在 `recomputeEnrollment` 的毕业判定（`const allPassed = d.chapters.length > 0 && d.chapters.every(c => c.passed)`）里完全不占权重，且 `runWorkExam` 只传了 `en.notebook.rules`，**漏装了最核心的老师傅技能卡 `skill` 和 `lessons`/`methods`**！
   - **影响**：对评测有效性严重损害。章节补考本质上是「看着判分点改同一道题」，考过 60 分只能证明模型听话照抄，不能证明学会了手艺；而真正考泛化的「真活考」既没装上老师傅技能卡（裸奔只带错题本），考砸了也不影响毕业。
   - **怎么改**：① `reflect` 提示词增加约束：「严禁把本题特有的具体数值、人名、偶发事件写进 rules，必须抽象成跨场景通用的触发条件与动作规则」；② `runWorkExam` 调用 `solveStaged` 时，必须把 `augmentSkill(skill, en.notebook, null, en.nova, methods)` 转成文本一并注入 `buildSolvePrompt`；③ 当课程存在 `related` 真活时，`recomputeEnrollment` 要求至少 1 道真活得分 ≥ `PASS_SCORE`（或 ≥ AI 基线）才置为 `graduated`。
   - **工作量**：中

5. **科研方法课、私域课、导师测评题三套模块与主培养链路脱节（写了代码但教务用不上）**
   - **证据**：① `src/lib/college-train.ts` 写了 `studyMethods`，但 `nextStep`、`advance` 以及 `src/lib/college-agent.ts` 的 `COLLEGE_TOOLS` 里**根本没有 `studyMethods` 工具或步骤**，AI 秘书和自动培养路径永远不会去修方法课；② `src/lib/college-private.ts` 写了 `privatePack`（「拼成私域知识包装进学员的作答提示」），但在 `college-train.ts` 和全套文件里**没有任何地方调用 `privatePack`**；③ `src/lib/college-exams.ts` 建了 `college_research_exams` 题库和导师校正，但和 `college_enrollments` 学籍、成绩单完全不互通。
   - **影响**：对科研客户（实验室/院所）和内部运营影响大。宣传的五层培养第 4 层（方法库）和实验室联合培养（私域知识包）在主流程里实际处于断路状态，运营靠学院秘书无法完成科研学员的完整培养。
   - **怎么改**：① 在 `nextStep` 中，若课程 `research === true` 且 `!nb.methods?.length`，在 `entrance` 后自动插入 `{ kind: 'methods' }` 步骤调 `studyMethods`，并在 `COLLEGE_TOOLS` 暴露 `study_methods`；② `skill_tasks`（或 `college_enrollments`）关联 `org_id` 时，`runChapterExam` 和 `runWorkExam` 自动调用 `privatePack(orgId)` 注入学员上下文和 `gradeCollege` 的 `given`；③ 明确 `college_research_exams` 作为科研专业的独立结业考挂入学籍表。
   - **工作量**：中

6. **公开毕业生页（`/college`）与教务处（`/college/admin`）对「谁是毕业生」的定义完全割裂**
   - **证据**：`src/lib/college.ts` 的 `listGraduates` 按 `skill_tasks`（空间）聚合，把同一空间下**所有不同模型**的作答混在一起算 `best(ai.filter(x => x.with_skill_id))`（第 61 行），只要历史上任意一个模型任意一章考过 60 分就标 `graduated: true`；而 `src/lib/college-admin.ts` 是按 `学员（单模型）× 空间` 建学籍，要求**同一模型在所有已发布章节**都 ≥ 60 且无诚信问题才算 `graduated`。
   - **影响**：对外展示与内部台账打架。教务处里某门课 0 人毕业（因为第 2 章没人过），前台 `/college` 却挂着「已毕业、最高 88 分」（拿了 A 模型第 1 章的分拼上 B 模型的名字），客户点进去核对学籍会发现数据对不上。
   - **怎么改**：改造 `src/lib/college.ts` 的 `listGraduates` 和 `graduateDetail`，直接基于 `college_enrollments`（状态为 `graduated` 或取该空间下表现最好的一份完整学籍）聚合展示，统一「全章通过 + 无诚信问题」的毕业口径。
   - **工作量**：中

7. **评卷提示词与防刷分存在两处规则漏洞：单句复制可拿 75% 分，文献与数字正则易漏判**
   - **证据**：① `src/lib/college-train.ts` 第 225 行 `else if (ev.length === 1) level = Math.min(level, 3)`，只要模型把题面或技能卡里的一句话嵌进回答被评卷人引为单句证据，上限仍高达 3 档（75% 分数），4 个维度全 3 档就是 75 分直接及格；② `fabricatedCitations` 只匹配英文 `et al.`、DOI 和 `中文1-4字+等(年份)`，模型编造《GB/T 99999-2023》《某某行业白皮书（2024）》或双人中文作者「张三、李四（2022）」完全绕过；③ `src/lib/college-honesty.ts` 的 `numbersNotInSource` 只抓前 20 个数字（`.slice(0, 20)`），长文前段塞满推算数字就能把后段编造的读数挤出检测窗口。
   - **影响**：评测防刷分能力受损，尤其在工程规范类、长报告类课程中容易漏放幻觉过关。
   - **怎么改**：① `fabricatedCitations` 增加国标/行标号正则（`\b(?:GB|GB\/T|ISO|ASTM|YY\/T|JGJ)[\s/\-]*\d+[\-\d]*`）和中文书名号报告+年份匹配；② `numbersNotInSource` 过滤掉列表序号（如 `1.` `2.`）后上限放宽至 50 个，或优先抽取带量纲/单位（`mg|mL|℃|MPa|%|元|小时|编号`）的数字；③ 评卷提示词要求 `level >= 3` 必须至少有 2 处独立证据，程序侧将 `ev.length === 1` 的上限从 `3` 收紧为 `2`（50% 分数）。
   - **工作量**：小

## 先别动的（2–3 条，说明理由）

1. **先别动「不微调权重、用五层可见材料装配」的培养架构（`college-train.ts`）**
   - **理由**：把学习过程外化为 `技能卡 + 章节要点 + 错题规则 + 方法卡 + 真活复盘` 是整套产品最聪明的设计——成本极低、每一条学到的规则对人类专家完全透明可删改，且天然免疫灾难性遗忘。当前要做的是把它的**导出交付**做实，千万别急着把它改成黑盒 SFT 微调流水线。
2. **先别动「程序算分 + 原话回查 + 双评自适应三评 + 诚信与手艺解耦」的 v2 评卷底座（`gradeCollege` & `college-honesty.ts`）**
   - **理由**：用 `flat()` 字符串比对强校验评卷模型引用的原话、分差 >10 自动触发第三次评卷取中位数并记录 `spread`（测量误差）、以及不让诚信封顶掩盖手艺真实得分的设计，在 LLM-as-a-Judge 领域是非常扎实的教育测量实践，只需修补单句档位上限和重评入参，不要推翻重写。
3. **先别动导师校正与实验室入口的「免注册 Token + AI 初稿人工只做确认/修改」交互（`college-exams.ts` & `college-private.ts`）**
   - **理由**：大牌导师和老师傅最怕注册登录和面对空白表单。发一条带 Token 链接直接改初稿并全量留痕 `corrections / history`，摩擦力极低，非常适合冷启动攒专家私有数据。

## 需要业务方拍板的问题（只列真正要人决定的）

1. **给买单企业/实验室最终交付的到底是什么形态？**
   - 目前「派去向（`college_placements`）」只是台账记录。客户付钱后，到底是交付**一段托管在平方工作台里的专属 Agent API**，还是允许客户**把五层知识包（含老师傅技能卡与错题规则）明文导出带回本地部署**？（这直接决定老师傅技能卡的知识产权保护边界与定价模式。）
2. **「老师傅」缺失时，`AI 草案（jd-draft）` 教出来的学员能不能发毕业证和对外派单？**
   - 代码里 `listCourses` 和 `listGraduates` 区分了 `teacher.expert`（真人老师傅 vs `jd-draft` AI 草案），但 `runChapterExam` 和 `recomputeEnrollment` 对 AI 草案技能卡照常发毕业状态。「AI 教 AI、AI 对照 AI 草案评卷」在商业承诺上是否允许算作正式「百业学院毕业生」，还是必须降级标为「预科 / 实训生」？
3. **公开排行榜（`Leaderboard`）与专业（`MAJORS`）如何保证跨模型公平性？**
   - 目前 `college-leaderboard.ts` 的总榜是「每个模型在**它自己考过的课**上取平均」——如果模型 A 只挑了 2 门简单客服课考 85 分，模型 B 考了 10 门硬核芯片/科研课得 75 分，总榜 A 会排在 B 前面。是否要拍板设立「基准必修课集（Benchmark Core）」，只有修满指定基准课的模型才能进总榜？
