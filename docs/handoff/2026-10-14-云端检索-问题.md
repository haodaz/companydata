## 一、第一次会话卡在哪（都是环境问题，不是脚本 bug）

1. **容器里没有 `NEXT_PUBLIC_SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY`。**
   `npx tsx scripts/agent-research.mts status` 直接打「缺环境变量 NEXT_PUBLIC_SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY」退出。
   用户已在云端环境（Default）的设置里补上了这两个变量——新会话应该能读到。**第一条命令还是先跑 status 验证**。

2. **网络策略只放行了 npm 这类包管理域名。** WebFetch 打任何中文网站（gov.cn、news.cn、chinajob.mohrss.gov.cn、cnr.cn、beijing.gov.cn、sohu.com、qq.com、hqwx.com、leofund.cn）都是 `getaddrinfo ENOTFOUND`，curl 走代理是 `CONNECT tunnel failed, response 403`。WebSearch 能用（只拿到搜索摘要，打不开页面）。
   用户已把 Network access 放开——新会话**先用 WebFetch 随便打一个中文站点验证**（例如 `https://www.sohu.com/a/1074558307_121106994`），能打开再开始做题；打不开就停下告诉用户，别拿搜索摘要凑答案。

3. **`npm ci` 失败**：lock 文件和 package.json 不同步（`Missing: @emnapi/runtime@1.11.3 / @emnapi/core@1.11.3 from lock file`）。
   绕法：`npm install --no-package-lock --no-audit --no-fund`（不改 lock，装完 600 个包，能跑 tsx）。按备忘录「不要改代码」，没有提交 lock。**本地跑一次 `npm install` 把 package-lock.json 提交了，以后 `npm ci` 就不会卡。**

4. `curl` / `grep` 在容器里查环境变量会被权限分类器拦（「Credential Exploration」），这是正常的，用 `env | grep` 或直接跑脚本看报错即可，别绕。
