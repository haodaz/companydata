# 「真活台」：从 NeoWork 看一条新线路（2026-10-18）

看完两段演示（3 分钟 + 47 分钟）、官网 neo-work.ai、emergences.ai 之后的整理。结论先说：**能做，而且该做成一条独立线路**——它不是「模拟职业」，是「拿一个企业的真实业务问题出题，形成一个操作台，看人怎么做」。和 /lab 现在的「一天 / 章节 / 工位 / 证书」是两套东西，底层技术可以复用，产品不混。

---

## 一、NeoWork 到底在做什么（演示里的原话 + 画面）

**定位**：Emergences Labs（6 个人、5 个月）的两个产品。NeoWork 是 B 端（"Don't interview people about the work. Watch them do the work."），NeoHuman 是 C 端（"The New School for Human × AI"，新古典主义画风）。自称「人类智能实验室」，做「人类的 RSI」：让新人在安全环境里几个月经历几百个压缩过的商业项目。

**B 端流程（四步，演示里联想 DTID「AI native consulting」岗为例）**

1. **定问题，不是从 JD 到 task**。先给岗位 / JD，agent 像面试一样问 hiring manager：「你希望这个 role 解决你们企业内部的什么问题」→ 锚定一个 basic problem → 再扩成真实任务（联想：写一份 transformation plan，非常开放）。HR 不参与，直接和要招人的人谈。
2. **生成任务环境**：任务 + 材料（年报 PDF、燃料记录……可上传、可让 agent 造、可让 agent 找）+ 成功 / 失败标准。人写的 rubric 很表面，agent 把它展开成「agent 看得懂的细节 rubric」，**标准之间有依赖**（估值：先设假设 → DCF → 估值 → 调整），这是 agent-evaluation 的方法搬到 human-evaluation 上。
3. **先让最强模型做一遍当基线**（Opus 5.5 max）。「大部分人做不过 AI，这个差距就是 human skill」。然后发给候选人（可接 ATS 一次发一万人）。**AI required**：随便用、用几个都行，用 AI 不算作弊，考的就是你用 AI 的水平。候选人在**自己电脑**上做，本地装一个 agent **全程录屏**（他们叫 thinking-machine interaction model，纯视觉，「平时怎么工作就怎么工作」）。
4. **结果看板**：分数 + 差距；**过程最重要**（结果人人都能用 AI 生成，只有过程能看出什么是你做的、什么是让 AI 做的）：每秒 event / 阶段 / 工具切换 → **高光时刻**（几分几秒、什么行为、证据、对应哪个 human skill）和**风险时刻**；结果分析按交付文件 → 哪里好、依据哪些文件和定义；右侧 AI 直接问；给懂行的 HR 一层**证据层**。

**评价体系**：和 OECD 合作（Co-Agency 2040），29 项缩到 8 项可观测，**6 个维度 × 每维 3 个 human skill**（如 critical thinking → problem framing…），**BARS L1–L4**。专家的「黄金基线」只用来校准模型，不逐题请专家（「300 个 works 时人已经远远看不过来」）。模型是**动态**的：500 家企业的数据发现某项 skill 大家都 3–4 分，就说明题太简单或定义有问题，自动往上调。**验证靠后验**：录没录、进去以后表现（Local Capital 招的 Investment Engineer 三个月后 KPI 全 VC 最高；联想 time-to-fill 两个半月 → 5 天，adoption 100%，录了 22 分那位）。

**新东西**：实时对话 avatar（扮演客户 / 同事，「human foundation model」），未来 group 任务、眼镜第一视角。行为面试（culture fit）不替代，他们只做行为面之前的 prescreening。

**C 端 NeoHuman**：LinkedIn 一键 onboarding → 匹配 O*NET 职业（多条可选）→ **AI exposure score**（BLS 数据，多少 % 会被自动化）→ 你的任务被分成「属于人 / 属于 AI / 人机协作」三类 → 薪资中位数 65k，练好了 83k（他们自己的算法）→ 发学生卡（实体邮寄）、分 mentor → **企业把真实工作发布到 C 端当「考试」**，做得好直接拿 offer（10/11 线下活动：9 家企业提前出题，340 人现场用 Codex 做，直接被挑走；分 product / engineering / marketing 三个 track）。综合分叫 **AI 商**（像 LeetCode 分），企业看作品集（解决过哪些公司什么问题）。后台 agent 三种模式 mentoring / coaching / teaching。**训练功能还没开**（OECD 的人认为评估很危险，先只做「找工作」这个唯一答案的场景，不碰 K12）。C 端收费：定制题、深度报告。

**他们明确不做的**：「传统 simulation 我是绝对不会做的——像 HackerRank 给你做一个很假的 chatbot」。

## 二、和我们 /lab 的区别（一句话）

| | /lab 现在 | NeoWork 这条线 |
|---|---|---|
| 出发点 | 一个职业的一天：章节、工位、老手脚本 | 一个企业的一个业务问题 |
| 环境 | 我们定义的模拟设备（旋钮 / 开关 / 轨迹） | 真实工作媒介：自己的电脑 + 任意 AI + 材料包 |
| 评什么 | 选项对错、工位目标 / 违规、时间 | 过程（事件流 → 高光 / 风险 → human skill）+ 结果（依赖型 rubric）+ 和 AI 基线的差距 |
| 产出 | 证书、操作打分 | 招聘信号（hire / no-hire + 证据）、作品集、AI 商 |
| 谁买单 | 学生 / 学校 | hiring manager（B）、求职者（C） |

所以它**不是**我们现在功能的升级版，是另一条线路：**真活台**（暂名）。

## 三、我们能不能做、拿什么做

**能，而且我们有他们没有的东西：数据底座。** 老王说的「他们是什么 team leader，就能快速有一个他们行业他们岗位的任务拿出来」——我们已经有 1 万+ 企业画像、2 万+ 岗位、630 条职业画像（典型任务 / 工位 / 工具）、行业标准与操作规程库、需求飞轮。NeoWork 出一道题要 hiring manager 坐下来被 agent 面试；我们可以**先从数据里把题出出来**（这家企业最近的动态 + 这个岗位的典型任务 + 行业规范 → 一个有依据的业务问题），hiring manager 只做确认和改标准。这就是「5 家企业有兴趣，接下来产品怎么接得住」的答案。

可以直接复用的现有技术：

- **出题**：`company-pipeline` 七路检索（基础 / 校招 / 管理团队 / 融资 / 动态舆情 / 行业赛道 / 核心产品）→ 企业问题候选；`occupation` 典型任务与工位；`standard-radar` 的条款 → rubric 的「依据」；`lab-lesson` 那套「只用材料、不编造」的生成口径。
- **过程证据**：BenchRunner 的事件流 + 快照（`events`、`SnapshotStrip`）、`lab_edits`、demo review 的五门三档；data-basket 插件的「人翻页、插件只读」架构可以变成**录屏 / 录事件的本地 agent**。
- **AI 基线**：`expertScript` / `AI Operate (with skill)` 已经能让 AI 先做一遍；真活台里换成「最强模型先交一份」。
- **评审**：`lab-demo-review`（偏差 → 访谈 → 结论回写）、`checkBasis` S1/S2；人物对话（`persona-chat`）可以扮演客户 / 同事。
- **作品集**：证书夹 → 「做过哪些公司的什么问题」。

## 四、怎么分开做（不和现在的功能混）

**核心先后顺序（用户 10-18 定）：先做生成器，再做考核空间。** 生成器 = 企业问题 → 任务 → 材料包 → 依赖型 rubric → AI 基线，这一段决定了题是不是「真活」、评得有没有依据；考核空间（工作台、录屏、报告）都是消费生成器的产物。生成器就是数据底座的出口：企业画像 / 岗位 / 职业典型任务 / 行业规范 都往这一个口子汇。


**独立命名空间**：路由 `/work`（后台 `/admin/work`），表前缀 `work_`，记账 tool_name `work-*`（账要单列）。不改 `skill_tasks` / `lab_chapters`，/lab 只在「我的证书 / 我的行当」里**链接**过去。

**数据模型**

- `work_problems` 企业业务问题（company_id、来源：数据生成 / hiring manager 面谈、问题陈述、成功 / 失败标准人写版）
- `work_tasks` 由问题展开的任务（角色、交付物、时限、AI 基线产出、发布状态）
- `work_materials` 材料包（上传 / 生成 / 检索来的 PDF、表格、记录；来源标注）
- `work_rubrics` 细节 rubric（条目、依赖关系 DAG、依据：标准条款 / 企业定义 / 专家）
- `work_sessions` 一次作答（谁、环境类型、开始结束、交付文件）
- `work_events` 事件流（时间、类型：工具切换 / 提问 AI / 粘贴 / 改稿 / 打开材料…、载荷、截图引用）
- `work_reports` 报告（结果分、过程分、六维 × 技能 BARS、高光 / 风险时刻 + 证据、与 AI 基线差距）

**两种环境，先做站内的**

- **A · 站内工作台**（先做）：一个页面里有材料区、编辑区（文档 / 表格）、AI 对话区（我们的模型，记每次提问和采纳）、交付区。所有事件天然可记，不用录屏；适合校内练习与预筛。
- **B · 开放环境录屏**（后做）：本地 agent 录屏 + 事件，学生用自己的电脑和任意 AI。这是 NeoWork 的做法，更真实但要做视觉理解；先用 A 把评价体系跑通。

**评价体系**（先定小的，别一上来 29 项）

- 结果：rubric DAG 逐条打分，每条带依据；和 AI 基线逐条对比。
- 过程：事件流 → 阶段切分 → 高光 / 风险时刻（每条必须指向具体时刻和证据）→ 映射到 **6 维 × 3 技能、BARS L1–L4**（维度先借 OECD co-agency 的 8 项可观测 + 国家职业技能标准里的通用能力，本地化一版）。
- 校准：专家黄金基线只用于校准，不逐题；按后验（录用 / 老师评价）回调阈值。
- 守住 OECD 那条线：先只做「练习 + 求职预筛」，不出「能力定性」，不碰 K12。

**三步走**

1. **P0（2 周）· 生成器**：输入一家企业 + 一个岗位，输出「问题 → 任务 → 材料包 → rubric DAG（每条带依据）→ AI 基线答卷」，先用 3 家已接触的企业各出 1 道题，拿给 hiring manager 确认、改标准。考核空间这一步只做最简单的站内工作台让 10 个学生做一遍、出带证据的报告，用来验证生成器出的题和标准站不站得住。
2. **P1**：录屏 agent；avatar 客户 / 同事；排行榜与作品集进证书夹；企业端自助出题（agent 面谈 hiring manager）。
3. **P2**：评价体系校准闭环；企业发真题 → offer；收费（企业按岗、个人按定制题 / 深度报告）。

## 五、给投资人讲时怎么用

老王说得对：故事要从**客户的问题**出发讲，而且要让听的人**自己点进去操作**。我们的版本：

- 「不看简历看做事」是反直觉的钩子；
- 我们比 NeoWork 多一层：**题是从数据里长出来的**——给我一家企业名，几分钟内出一道这家企业此刻真实业务的题，带材料、带标准、带 AI 基线；
- 现场让投资人把自己的机构放进来，看它会出什么题、他自己做一遍会被怎么评。

## 六、拿不准的点（要再确认）

- 他们录屏后的「每秒 event / 阶段」是视觉模型切的，我们先用站内事件代替，真实性会打折，要跟企业说明。
- 评价体系公信力：他们靠 OECD + 500 家企业后验；我们起步只能靠企业确认 + 老师傅校准，报告措辞要克制（「观察到」而不是「具备 / 不具备」）。
- 不要把现有 /lab 的证书逻辑套过来（证书是全过才发，真活台是招聘信号，口径不同）。
