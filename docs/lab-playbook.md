# 百业样板库：把「你我手工生职人」变成平台能学的东西

2026-10-12 起。终局是平台上的 AI-native 程序自己生出数字职人（多个子 agent + 环节拼装），手工只做样板。
这份文档是**口径**（模板、形态、规则），结构化样例在 `docs/lab-playbook.json`（`npx tsx scripts/lab-playbook-export.mts` 重新导出），
3D 场景的成败样本在 `scripts/beta3d/runs.jsonl`。

推进顺序：① 3D 流水线自动化 ✅ → ② 样板库（本文）→ ③ 规则校验器 → ④ 台面组件化 → ⑤ 人工修改留痕 → ⑥ 编排器。

## 一、交互故事模板（22 个样例共有的骨架）

每个台面的 spec 文件头都按这个顺序写，生成 agent 也按这个顺序产出：

| 槽位 | 问的是 | 例 |
|---|---|---|
| 场景与任务 | 谁、在哪、这一班要干成什么 | 110 kV 清枫线 112 间隔检修前做安全措施 |
| 你控什么 | 手上能动的东西（控件，多为隐藏控件由台面写入） | 氧枪枪位、供氧流量、石灰 / 矿石下料 |
| 你盯什么 | 要看的读数 / 现象（仪表、画面） | 熔池温度、碳、炉渣、冷却水 |
| 该做的顺序 | 老手的正确路径（= 示范脚本） | 验电器自检 → 验电 → 先接地端后接导体端 |
| 中途突发 | 第 N 分钟出事，逼出取舍 | 第 150 秒冷却水流量掉 |
| 烟雾弹 | 看着像问题其实不是（考判断，不考记忆） | 历史报警 E07、发黑但没坏的接触器 |
| 红线 | 违规（violation），每条都是真实事故类型 | 没验电就挂地线 |
| 数采点 | 一二产必填：真设备上会采的点位 | 速度、厚度、料温、料斗余量 |
| 时间缩放 | 1 秒真实 = N 秒模拟，让一段活 2–4 分钟走完 | 1 模拟秒 = 1 分钟 |
| 免责 | 「教学化简化模型，数值不是真实参数」 | |

## 三、规则清单（第 3 步校验器照这个实现）

「怎么查」：**码** = 代码硬校验（error 拦发布 / warn 提醒）；**评** = AI 评审 agent 打分给理由；**人** = 只能人看。

### 一天与章节
| 编号 | 规则 | 来源 | 怎么查 |
|---|---|---|---|
| D1 | 按时间排；内容配得上时段（别一大早复盘、中午交接班） | 用户 10-09 | 码（已有 lab-studio.ts） |
| D2 | 前后接得上：后面的章接住前面发生的事 | 用户 10-09 | 评 |
| D3 | 选择题可以有，但**一天至少一章真动手的台面** | 用户 10-11 晚 | 码 |
| D4 | 指挥 / 办公类职业也要有一线动手的章（应急加河堤） | 用户 10-11 晚 | 评 |
| D5 | 给人看的文字不出现角色编号（S03、N1） | 10-11 decode-cast-refs | 码 |

## 四、样例怎么用

- **few-shot**：生成某个职业的台面时，按「形态」从 `lab-playbook.json` 里挑两三条同形态样例的 `design` 塞进提示词。
- **评测集**：同一个职业名让 agent 重生一遍，和样例比（形态选得对不对、红线是不是真实事故类型、示范脚本能不能干跑过）。
- **加新样例**：新台面 spec 文件头照「一」的槽位写，导出脚本自动收进来；干跑不过的会标 ✗，不能拿去教。
